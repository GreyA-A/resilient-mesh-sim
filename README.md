# ResilientMesh — Мультиплатформне середовище імітаційного моделювання mesh-мереж

[![Cross-Platform Build & Verification](https://github.com/GreyA-A/resilient-mesh-sim/actions/workflows/ci.yml/badge.svg)](https://github.com/GreyA-A/resilient-mesh-sim/actions)

Програмний комплекс для моделювання самоорганізованих бездротових сенсорних мереж, верифікації протоколів передавання даних та аналізу стійкості зв'язку в умовах радіоелектронних завад (РЕБ).

Проєкт розробляється в межах курсу «Мультиплатформне програмування».

---

## Загальна інформація
* **Напрям досліджень кафедри:** 6. Моделювання, симуляція та верифікація програмно-апаратних систем
* **Тема проєкту:** Програмне забезпечення імітаційного моделювання та аналізу відмовостійкості бездротових mesh-мереж в умовах радіоелектронних завад
* **Формат виконання:** Індивідуальний проєкт (Соло)
* **Виконавець:** Куценко Артур, студент групи ІПЗ-31

---

## Зона відповідальності (Зріз 0 — Експертний рівень, критерій D1)
Проєкт реалізується одноосібно та охоплює повний цикл проектування:
1. **Платформонезалежне ядро обчислень (`MeshSim.Core`):** моделі топології, сутності пакетів, валідація станів, сувора обробка помилок.
2. **Дискретно-подійний симулятор (`MeshSim.Engine`):** черга подій передавання даних, динамічний перерахунок маршрутів, моделі зон радіозавад (вмикання/вимикання, переміщення, інтенсивність).
3. **Робота з файловими даними (критерій C5):** збереження та експорт звітів симуляції (JSON/CSV) з контролем цілісності та валідацією схем.
4. **Кросплатформний інтерфейс (`MeshSim.Desktop`):** інтерактивна візуалізація топології на базі Avalonia UI (Windows, Linux, macOS).
5. **CI/CD та якість:** матрична збірка Ubuntu/Windows, статичний аналіз коду (0 зауважень), покриття автотестами >= 80%.

## Інструкція із запуску (Критерій E3: запуск без втручання автора)

### Системні вимоги:
* Встановлений [.NET 8.0 SDK](https://dotnet.microsoft.com/download/dotnet/8.0), версія **8.0.319 або новіша в межах 8.0.x** (вимога `global.json`). Якщо в системі є лише SDK 9+, `dotnet` відмовиться збирати проєкт, тому встановіть SDK 8.0 поруч.
* Git.
* Підтримувані ОС: Windows 10/11, Ubuntu 22.04+, macOS 12+.

### Кроки для збірки та перевірки:

1. **Клонувати репозиторій:**
   ```bash
   git clone https://github.com/GreyA-A/resilient-mesh-sim.git
   cd resilient-mesh-sim
   ```
2. **Відновити залежності:**
   ```bash
   dotnet restore
   ```
3. **Скомпілювати рішення у режимі Release:**
   ```bash
   dotnet build ResilientMesh.sln --configuration Release --no-restore
   ```
4. **Запустити автотести (таблицю покриття Coverlet буде виведено в консоль, звіти `coverage.json` та `coverage.cobertura.xml` з'являться в каталозі `TestResults/coverage/`):**
   ```bash
   dotnet test ResilientMesh.sln --configuration Release --no-build --verbosity normal
   ```
5. **Запустити графічний інтерфейс:**
   ```bash
   dotnet run --project src/MeshSim.Desktop
   ```
   Журнал роботи пишеться в `%LOCALAPPDATA%\MeshSim\logs` (Windows) або `~/.local/share/MeshSim/logs` (Linux/macOS) у файли `meshsim-РРРРММДД.log`.

> **Примітка для Linux:** на мінімальних дистрибутивах без графічних бібліотек застосунок може не стартувати. Встановіть `libfontconfig1` (наприклад, `sudo apt install libfontconfig1`).

## Приклади сценаріїв та файли

Каталог `scenarios/` містить готові сценарії (JSON, версія схеми 1). Відкрийте їх у застосунку кнопкою «Відкрити сценарій…».

| Файл | Що демонструє |
|---|---|
| `jammed-reroute.json` | Пряму лінію заглушено зоною РЕБ, пакети йдуть в обхід через вузол `B`; друга зона вимкнена |
| `battery-depletion.json` | Ретранслятор `R1` вичерпує заряд: один пакет втрачається, наступний іде через `R2` |
| `network-partition.json` | Зона завад розділяє мережу на дві частини: пакет між частинами втрачається (`NoRouteFound`) |

Звіти експортуються у JSON (метрики, втрати за причинами, журнал подій) та CSV (журнал подій). Поруч із кожним файлом створюється файл контрольної суми `*.sha256`. JSON-звіт можна відкрити в застосунку: перед показом перевіряється SHA-256 та узгодженість даних, а змінений чи пошкоджений файл відхиляється з повідомленням.

## Приймальне тестування

Фіксований перелік із восьми приймальних кейсів `AC-01…AC-08` (обхід зони завад, виснаження ретранслятора, розділення мережі, керування прогоном, редагування сцени, збереження сценарію, експорт та імпорт звітів, стійкість до пошкоджених файлів) описано в [ACCEPTANCE.md](ACCEPTANCE.md): для кожного кейса є ручна процедура в інтерфейсі, очікуваний результат і посилання на автоматизований наскрізний тест. Лише приймальні тести:

```bash
dotnet test ResilientMesh.sln --configuration Release --filter "FullyQualifiedName~AcceptanceTests"
```

## Якість і CI

Збірка вважає попередження помилками (`TreatWarningsAsErrors`), аналізатор працює в режимі `Recommended`. Попередження NuGet Audit про недоступність джерела пакетів (`NU1900`) та про вразливості залежностей (`NU1901–NU1904`) лишаються попередженнями й збірку не ламають, але їх видно в логах.

Покриття збирає єдиний механізм `coverlet.msbuild`. Типові команди:

```bash
# Швидкий цикл: тести з таблицею покриття, без перевірки порогу (працює і з --filter)
dotnet test ResilientMesh.sln --configuration Release

# Повна перевірка, як у CI: поріг 100% для Line, Branch та Method кожного модуля
dotnet test ResilientMesh.sln --configuration Release /p:Threshold=100
```

Не поєднуйте `--filter` із `/p:Threshold`: запуск частини тестів завжди дає неповне покриття. У GitHub Actions (Ubuntu та Windows) поріг задає змінна `COVERAGE_THRESHOLD` у `.github/workflows/ci.yml`, а звіти покриття кожної ОС публікуються як артефакт `coverage-<ОС>` (вкладка «Summary» запуску).
